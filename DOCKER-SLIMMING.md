# RestPoint — Docker Image Slimming & Dependency Cleanup

> **TL;DR** The production Docker images were ~3 GB each (47.6 GB for all 40) because
> every service shipped its full dev toolchain, all `devDependencies`, a global
> `tsx`, and a `chown -R` layer that duplicated the whole app (+504 MB). The
> build cache added another 12 GB. This document describes the fix and how to
> reclaim the disk on the server.

## What changed

### 1. Multi-stage Dockerfiles (biggest win)

Every `services/<name>/Dockerfile` is now a **4-stage** build generated by
`scripts/generate-dockerfiles.mjs`:

| Stage | What it does | Shipped? |
|-------|--------------|----------|
| `deps` | Full dependency tree (manifests only) for compiling shared packages | no |
| `build` | Compiles `packages/*` TypeScript → `dist/` (needs `typescript`, `g++`…) | no |
| `prod-deps` | `npm install --omit=dev` — production `node_modules` only | no |
| `runtime` | `node:24-alpine` + `dumb-init` + prod deps + built `dist/` + sources | **yes** |

**Before → after** (representative):
- `restpoint-deceased-service`: **3.14 GB → ~459 MB** (−85 %)
- The old `chown -R nodejs:nodejs /usr/src/app` layer was **+504 MB**; now the
  equivalent `mkdir`/`chown` on the (empty) upload dir is **~4 KB**.
- No more `python3`, `make`, `g++`, `typescript`, `nodelog` in the image.

Runtime sources are copied with `COPY --chown=nodejs:nodejs`, so ownership is
set at copy time — no separate chown layer at all.

**Regenerate after editing:** `npm run docker:gen`

### 2. Dependency cleanup

`scripts/scan-dependencies.mjs` walks every workspace and reports, per package:
- **UNUSED** — declared but never imported anywhere (removal candidates)
- **PHANTOM** — imported but only resolves because npm hoisted another
  workspace's copy (breaks standalone installs)
- **USED-ONLY-ELSEWHERE** — dead weight when declared in `package.json` root

`scripts/fix-dependencies.mjs` applies the curated cleanup:

**Root `package.json` removed** (frontend libs that leaked into the backend,
plus heavyweight/unused packages):
`puppeteer` (was downloading Chrome into **every** build!), `three`,
`chart.js`, `react-router-dom`, `react-signature-canvas`, `tesseract.js`,
`prop-types`, `bcryptjs`, `braces`, `bull`, `compression`, `csurf`,
`exceljs`, `path-to-regexp`, `pino-loki`, `to-regex-range`, `sharp`,
`axios`, `helmet`, `hpp`, `http-proxy-middleware`, `ioredis`, `knex`,
`multer`, `node-cron`, `express-rate-limit`, `express-session`,
`@types/{bcryptjs,cookie-parser,express-session,validator}`, and dev-only
`pino`, `vite-plugin-compression2`, `@types/{pino,hpp}`.

**Phantom dependencies declared** in the workspaces that actually use them
(so the slim `--omit=dev` Docker installs still resolve):
- `packages/shared-logger` ← `pino-loki` (used as a pino transport string)
- `packages/shared-services` ← `sharp`, `redis`
- `packages/shared-config` ← `express` (type-only)
- `shared` ← `axios`, `prom-client` (runtime), `express` (type-only)
- `services/auth-service` ← `helmet`, `express-rate-limit`, `redis`, `yargs`
- `services/billing-service` ← `pino`
- `services/bodycheckout-service` ← `axios`, `sharp`
- `services/coffin-service` ← `axios`
- `services/deceased-service` ← `pdfkit` (promoted to runtime deps)
- `services/florist-service` ← `axios`, `knex`, `multer`
- `services/hearse-service` ← `node-cron`
- `services/socketio-service` ← `cors`, `express-rate-limit`
- `services/workshop-service` ← `axios`, `knex`
- `FrontendClient/client` ← `tesseract.js`

**`npm install` result:** removed **350 packages**, added **82** (net −268).

### 3. Repo-wide `--legacy-peer-deps`

`bullmq@5` declares `peerOptional redis>=5` while this stack standardizes on
`redis@4.7.1` (chosen by `socketio-service`). The legacy `leave-service`
Dockerfile already worked around this with `--legacy-peer-deps`. The generator
now applies it to every install — safe, and required for a clean resolution.

## Server disk reclamation

Run on the production server:

```bash
# 1. See current usage
docker system df
npm run docker:df

# 2. Preview what will be reclaimed
npm run docker:prune:dry

# 3. Reclaim it
npm run docker:prune
```

`scripts/docker-cleanup.mjs` safely removes:
1. **Build cache** (>24 h old) — was **12.15 GB**
2. **Dangling images** (untagged intermediate layers)
3. **Orphan `<svc>:latest` images** where `restpoint-<svc>:latest` exists
   (e.g. a stray `florist-service` alongside `restpoint-florist-service`);
   only deletes those not in use by a running container.

It **never** touches named data volumes (`mariadb_data`, `redis_data`,
`rabbitmq_data`, `monitoring_grafana-data`, `monitoring_prometheus-data`,
`monitoring_loki-data`, …) or images a running container references.

### Why `overlay` wasn't found

The `overlay` command doesn't exist in Debian/Ubuntu. To inspect the actual
storage driver usage (where the bulk of image data lives) use:

```bash
du -xh --max-depth=1 /var/lib/docker/overlay2 2>/dev/null | sort -h | tail -20
```

The named volumes are small (~1.1 GB); the 47.6 GB was in images + build cache,
reclaimed by the prune above and by rebuilding with the new multi-stage
Dockerfiles.

## Rebuilding everything

```bash
npm run docker:build        # parallel build of all services (uses cache)
docker compose up -d        # (re)start with the slim images
```

## Maintenance

- **Edit a Dockerfile?** Don't — edit `scripts/generate-dockerfiles.mjs`
  `SERVICES` and re-run `npm run docker:gen`. The files are generated.
- **Add a phantom dependency?** Run `npm run scan:deps` to detect it.
- **Verify nothing regressed:** `npm run build` (typechecks all workspaces).
